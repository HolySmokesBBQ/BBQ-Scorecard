# BBQ Board — iOS setup runbook

Status: scaffold built on Windows from Scorecard's ios/ template, then rewritten with Board's identity. Not yet built, not yet uploaded to Codemagic.

## What's done in this scaffold

- `ios-board/App/App.xcodeproj` — Xcode project cloned from Scorecard's, with:
  - Bundle ID `com.holysmokesbbq.board` (2 occurrences in `project.pbxproj`)
  - `CURRENT_PROJECT_VERSION = 1` (Board's iOS starts fresh, not Scorecard's build 3)
  - `MARKETING_VERSION = 1.0`
- `App/App/Info.plist` — `CFBundleDisplayName = BBQ Board`, `ITSAppUsesNonExemptEncryption = false` (skips App Store Connect's "Missing Compliance" prompt every build). Location/camera/photo permission strings inherited from Scorecard's Info.plist and left in place — harmless if unused, avoids future permission crashes if Board ever adds them.
- `App/App/capacitor.config.json` — Board runtime config: `appId com.holysmokesbbq.board`, `webDir dist-board-native`, `FirebaseAuthentication providers: [google.com]`.
- `App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-512@2x.png` — 1024×1024, opaque, alpha stripped. Generated by `scripts/gen-board-ios-icon.mjs` (rerun to regenerate from `public/BBQ Board/BBQ BOARD.512.png`).
- `App/App/GoogleService-Info.plist` — **PLACEHOLDER**. Deliberately invalid so a build against it fails loud rather than silently connecting to Scorecard's Firebase. Replace before first Codemagic run.
- `App/App/public/.gitkeep` — placeholder so the `public/` dir exists. Populated by Capacitor's `cap sync ios` step in `codemagic.board.yaml` at build time.
- `../codemagic.board.yaml` — Codemagic pipeline. Points at `ios-board/App/App.xcodeproj`, scheme `App`. `submit_to_testflight: false` for now — flip to true when ready.
- Web layer (Board's App.board.jsx et al.) is shared with Android. iOS-specific: `index.board.html` has `viewport-fit=cover` and `#root` has `env(safe-area-inset-top/bottom)` padding so content doesn't draw under the iPhone notch or home indicator.

## What Joel still has to do before the first Codemagic run

1. **Register bundle ID** `com.holysmokesbbq.board` at developer.apple.com → Certificates, Identifiers & Profiles → Identifiers → +.
2. **Create App Store Connect app record** at appstoreconnect.apple.com → My Apps → + → New App. Name "BBQ Board — Meat Prices", category Shopping or Food & Drink.
3. **Create Firebase iOS app** in project `holy-smokes-bbq-board` → Project settings → Add app → iOS. Bundle ID matches step 1. Download the real `GoogleService-Info.plist` and drop it at `ios-board/App/App/GoogleService-Info.plist` (overwriting the placeholder). Then `git add -f` it — the default `.gitignore` blocks Google service files.
4. **Register the Codemagic integration** (App Store Connect API key). Reuse Scorecard's team-level key if it already exists — the `codemagic.board.yaml` currently references `BBQ_Scorecard_ASC_KEY`. If you want a Board-specific key, register a new one and swap the name in the yaml.
5. **Cert key** — reuse Scorecard's `CERTIFICATE_PRIVATE_KEY` in the `appstore_credentials` env group. Apple's Distribution certificate covers all bundle IDs on the same team, so no new key needed unless you want isolation.
6. **Repo strategy** — Board's source is currently all untracked. Codemagic pulls from GitHub; the whole source (`src/`, `public/`, `capacitor.board.config.ts`, `vite.config.native.board.js`, `ios-board/`, `codemagic.board.yaml`) must be committed to a repo Codemagic watches. Simplest: same repo Scorecard uses (`HolySmokesBBQ/BBQ-Scorecard`), Codemagic app pointed at `codemagic.board.yaml`. Cleaner: new `HolySmokesBBQ/BBQ-Board` repo.

## Known gaps

- **Sign in with Apple.** Board is Google-sign-in-only. Apple guideline 4.8 requires Sign in with Apple when third-party sign-in is offered on a login-required app. If Board goes to the App Store requiring sign-in, this needs to be coded first. (Sign-in is optional in Board — you can browse without one — which may or may not be enough for Guideline 4.8.)
- **On-device visual check.** Nothing in this scaffold has been run on real iOS hardware. First real compile will surface things the Windows scaffold can't see. Budget for a handful of build failures per Scorecard's history (they hit 9 before green — see the shared `ios-codemagic-build` memory).
- **SDK 36 edge-to-edge risk** applies here too (same `env(safe-area-inset-*)` guardrail). Do NOT promote from TestFlight to public App Store without a real-device look at the header (BBQ BOARD row) and bottom controls.
